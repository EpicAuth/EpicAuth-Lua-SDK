# Security & Integrity Model

EpicAuth Lua SDK implements multiple layers of client-server security matching the official TypeScript SDK.

---

## 1. Response Signature Verification (Ed25519)

All server responses (except binary downloads and log posts) include cryptographic authentication headers:
- `x-signature-ed25519`: Hex-encoded Ed25519 signature generated by the EpicAuth server.
- `x-signature-timestamp`: Unix timestamp of the signature creation.

The SDK verifies that the signature matches `timestamp .. response_body` using EpicAuth's public key:
`95b38710f40927b16528a073b87d942e03bd4578d49963a19ebae177945f89ac`

If an Ed25519 library (`monocypher`, `luasodium`, or `tweetnacl`) is installed, the SDK performs hardware-grade verification. Tampered responses immediately abort with:
`Signature checksum failed. Request was tampered with or session ended most likely.`

---

## 2. Anti-Replay Timestamp Protection

To protect against MITM replay attacks, the SDK compares the server's `x-signature-timestamp` header with the local system clock.

If the time difference exceeds **25 seconds**, the request is rejected with:
`Time difference is too large: ... seconds, try syncing your date and time settings.`

---

## 3. Hardware ID (HWID) Locking

`app:getHWID()` extracts machine-specific attributes:
- **Windows**: `MachineGuid` from `HKLM\SOFTWARE\Microsoft\Cryptography`, with fallback to user account SID via WMIC.
- **Linux**: `/etc/machine-id` or `/var/lib/dbus/machine-id`.
- **macOS**: `IOPlatformSerialNumber` via `ioreg`.
- **Generic Fallback**: SHA-256 digest of hostname, username, CPU model, and system architecture.

Keys can be locked to a single HWID in the EpicAuth dashboard to prevent unauthorized sharing.

---

## 4. Local Audit Log Sanitization

When `loggingEnabled = true`, logs written to `~/.epicauth/logs/<exeName>/` automatically redact sensitive fields:
- `sessionid`
- `ownerid`
- `app`
- `version`
- `fileid`
- `webhooks`
- `nonce`

This prevents accidental credential exposure in application logs.
